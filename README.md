# AutoSystemDesignArticle

Научная статья о методах **проектирования и проверки микросервисных архитектур по функциональным и нефункциональным требованиям**, включая синтез с помощью больших языковых моделей, аналитические модели очередей и дискретно-событийное моделирование.

Исследование разрабатывается поэтапно. Описания запланированных экспериментов **не являются** утверждениями о полученных результатах. Исходный исследовательский проект: [AutoSystemDesign](https://github.com/Volodya1000/AutoSystemDesign).

## Компиляция PDF

Нужны `latexmk`, `pdflatex`, `bibtex`, пакеты `texlive-latex-recommended`, `texlive-latex-extra`, `texlive-fonts-recommended`, `texlive-lang-cyrillic`.

```bash
latexmk -pdf -gg -interaction=nonstopmode -halt-on-error -file-line-error main.tex
mv main.pdf article.pdf
```

Главный файл: `main.tex`. Текст статьи: `content.tex`. Оформление: `preamble.tex`. Источники: `bibliography.bib`.

Для очистки временных файлов: `latexmk -c main.tex` (PDF сохраняется).

## Автоматическая сборка

Workflow `.github/workflows/build-pdf.yml`:

- собирает PDF с библиографией на каждом PR, при изменениях исходников в `main` и по ручному запуску;
- проверяет, что PDF создан и ссылки/цитирования разрешены;
- прикрепляет PDF как артефакт GitHub Actions;
- **коммитит `article.pdf` в ветку PR из этого же репозитория** или в `main` после push, только когда содержимое действительно изменилось.

Для PR из форков PDF доступен в артефактах, автоматическая запись в сторонние ветки не выполняется. Для коммитов файла используется `github-actions[bot]`.

## Принципы научного изложения

Формулы сопровождаются определением переменных и предпосылок; при первом употреблении иностранного термина раскрывается сокращение и приводится русский эквивалент. Гипотезы, планы экспериментов и измеренные результаты не смешиваются. Исследуются методы проверки и сравнения архитектур, а не особенности CI или объектно-ориентированной реализации.
